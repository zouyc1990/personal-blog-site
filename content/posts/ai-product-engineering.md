## 顶层思维：AI 产品的核心不是模型

模型能力会持续扩散，单纯“接入大模型”很快会失去差异。真正要判断的是这个产品有没有形成闭环。

一个 AI 产品至少要回答四个顶层问题：

- 任务是否足够高频，用户是否愿意在这里停留
- 输入上下文是否独特，是否会随着使用越来越懂用户
- 输出质量是否能被评测，而不是只能靠感觉
- 结果是否能进入业务流程，而不是停在聊天窗口

## 底层拆解：RAG 不是把文档塞进向量库

一个可用的 RAG 链路至少包含：

1. 文档切分：按语义边界切，而不是机械固定长度
2. 向量召回：保证相关内容能进入候选集
3. 关键词召回：补齐专有名词、编号、接口名
4. rerank：把候选内容按问题相关性重新排序
5. prompt 组装：控制上下文、格式和不可回答策略
6. 评测：用固定问题集看命中率、引用准确率、幻觉率

## 技术抓手

- chunk size 不能只看 token 数，要看信息是否完整
- top_k 过大会增加噪声，过小会漏召回
- prompt 必须要求引用来源，否则很难定位错误
- 评测集要覆盖简单事实、跨文档综合、无答案问题
- 线上要记录 query、retrieved chunks、answer、latency、cost

## 一个 RAG 评测样例

```json
{
  "question": "支付接口超时后系统会重试几次？",
  "expected_sources": ["runbook/payment-timeout.md"],
  "expected_answer": "最多重试 2 次，并使用指数退避。",
  "checks": ["source_hit", "answer_grounded", "no_extra_policy"]
}
```

顶层决定这个 AI 能不能创造价值；底层决定它能不能稳定交付价值。
